# BGS 64D 加權線上學習 A/B 測試面板

BBB 網頁版維持 32D 牌靴進程 + 32D 路單結構，共 64 維 Context，並同步運行兩組 two-arm LinUCB：

- 主模型：牌靴 60% / 牌路 40%
- 對照組：牌靴 50% / 牌路 50%

兩個 32D 區塊先分別做 L2 正規化，再用 `sqrt(weight)` 縮放。這是因為 LinUCB 的不確定性項使用 `xᵀA⁻¹x`，如此才能讓區塊能量接近指定的 60/40 或 50/50，而不是用特徵數量假裝權重。

## 操作與延遲學習

1. 用「莊 / 閒 / 和」輸入起始歷史；尚未產生預測時，只會增加歷史。
2. 按「開始分析」，主模型與對照組會使用同一份歷史，各自產生下一局 B / P 預測。
3. 下一局開出後，按下實際的「莊 / 閒 / 和」：
   - 結算上一筆待處理預測。
   - 更新累計勝率、最近 20 局勝率、最長連輸與 Brier Score。
   - 莊 / 閒結果分別更新兩組模型的 A/b；和局記為 Push，不計勝負且不更新 A/b。
4. 再按「開始分析」，預測下一局。

系統不會用結果回頭重算已經發出的預測，也不做 Walk-forward 偷看；只有下一局實際結果輸入後，才進行 one-step delayed feedback。

## 公平 A/B 比較

- 兩組模型使用相同的 64 個原始特徵、相同 LinUCB 參數與相同結果序列。
- 唯一實驗變因是牌靴 / 牌路的區塊權重。
- 兩組使用獨立 A 矩陣、b 向量、選擇狀態與延遲更新。
- Brier Score 越低越好；和局不進入勝率與 Brier 分母。
- 「返回上一局」會移除對應結算，並從保留的結算紀錄重建兩套模型與統計。

## 64D 特徵限制

按鈕版沒有 A～10/J/Q/K 的實際殘牌輸入，因此牌值比例會先中心化為 `(ratio - 1)`，缺少牌值資料時使用 neutral 0，避免常數 1 在 L2 正規化時吃掉假的牌靴權重。physical edge 與 exact composition reliability 仍為 0；其餘維度來自牌靴進度、階段、樣本支撐、和局比例、資訊熵，以及長短窗路單結構訊號。

## 舊版本資料遷移

首次載入新版時，如果瀏覽器只有舊 32D 或上一版 64D localStorage：

- 保留 B / P / T 歷史紀錄。
- 不混用舊模型矩陣與舊統計。
- 同時建立乾淨的 60/40 主模型與 50/50 對照組，A/B 統計從零開始。
